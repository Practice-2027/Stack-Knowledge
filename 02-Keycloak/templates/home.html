🔄 How Authentication Works

  1. Login Request: Clicking "Sign In" redirects you to Keycloak server at http://localhost:8088/realms/notes-app/protocol/openid-connect/auth.
  2. Identity Check: Keycloak validates credentials or lets users self-register.
  3. Authorization Code: Keycloak redirects back to /callback with a temporary authorization code.
  4. Token Exchange: The Flask backend exchanges the code for JWT tokens (Access, ID, Refresh).
  5. Session & RBAC: The app decodes the token claims and restricts views by role.

Core Keycloak Concepts

🏰 Realms

A realm manages a set of users, credentials, roles, and groups. Our realm is notes-app, completely isolated from Keycloak's default master administration realm.

📱 Clients

Clients are applications and services that request authentication from Keycloak. Our Flask app is registered as confidential client notes-client with an authenticating secret.

🛡️ Role-Based Access (RBAC)

Keycloak assigns roles like user and admin to accounts. These roles are digitally embedded inside the signed JWT token claims evaluated by Flask.
