Inspect the real repository before writing documentation.

Repository files, source code, configuration, dependencies, APIs, prompts, databases, deployment files, logging, errors, and tests.

## Required understanding and workflow

1. Map the repository.
2. Identify implemented technologies and data flow.
3. Record evidence from filenames and code.
4. Mark anything absent as NOT IMPLEMENTED IN THIS PROJECT.
5. Separate production recommendations from current behavior.

## Workflow

```text
Repository -> evidence collection -> implementation map -> gaps and recommendations -> documentation
```

## Evidence rule

- Inspect the repository and cite the relevant file or configuration before describing implementation behavior.
- If a feature is missing, write `NOT IMPLEMENTED IN THIS PROJECT`.
- If it is only a recommendation, write `PRODUCTION RECOMMENDATION - NOT CURRENTLY IMPLEMENTED`.

## Output expectation

The finished project documentation should explain this topic from beginner level through engineering-level detail, with concrete examples derived from the actual code.
